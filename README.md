# 유리 너머 — 첫 인터랙션 프로토타입

## 관성 변형에 맞춘 물길 너비 — 2026-10-08

물방울의 관성·회전 모양을 갱신한 뒤 해당 프레임의 물길을 기록합니다. 늘어진 몸 전체의 투영 폭 대신 렌더링 스프라이트의 허리 변형을 반영한 몸통 중앙 단면을 사용합니다. 따라서 가늘어진 방울이 굽어 이동할 때 세로 길이까지 물길 폭으로 부풀려지는 현상을 줄입니다.

물길은 방울별 이전 폭에서 현재 폭으로 이어지는 짧은 가변 너비 구간입니다. 방울이 지나가지 않은 앞쪽까지 넓게 지우던 둥근 끝부분을 제거했습니다. 손가락 획은 기존 둥근 끝부분을 유지합니다. 방울이 정지했다가 출발하거나 손가락으로 모아 재출발하면 이전 폭 연결을 초기화합니다. 과거 물길을 다시 그리거나 전체 폭을 소급 변경하지 않으며 1.5초 유지·1초 김서림 복구도 유지합니다.

별도 너비 노이즈 없이 현재 모양의 너비 계산과 새 구간의 마스크 영역만 갱신합니다. 전체 자동 테스트 308개 통과: 30/60/120Hz 관성 갱신 순서, 가늘어짐·퍼짐에 따른 경로 폭, 굽은 경로의 과도한 폭, 전방 지움 방지, 구간 연결·과거 폭·김서림 복구와 기존 기능을 확인했습니다.

## 비의 양과 유리 표면 마찰 — 2026-10-08

메뉴의 `비의 양` 슬라이더로 새 비를 0–200% 범위에서 조절합니다. 100%는 기본 생성량이며 일반 방울의 생성 빈도, Heartfelt 이동 방울의 후보 밀도, 미세 방울의 새 등장·결로에 함께 적용합니다. 0%는 새 비를 중단하며 이미 맺힌 물의 낙하·합체·물길은 계속됩니다. 낮춘 밀도는 기존 물을 삭제하지 않고 이후 등장부터 반영됩니다. 초기화하면 현재 설정에 맞춰 다시 맺힙니다. 기본 크기·질량·바람·음악 설정은 슬라이더가 변경하지 않습니다.

일반 방울과 새 결로는 일정 간격 대신 누적 생성률에 무작위 도착 간격을 적용합니다. 기존 개수 상한(일반 물리 방울 최대 420개, Heartfelt 이동 방울 900개, 미세 방울 필드 22200개)을 유지하므로 포화 상태에서는 200%가 화면상의 개수를 정확히 두 배로 만들지는 않습니다. Heartfelt 미세 방울은 다음 등장 주기부터 셰이더 알파와 충돌 가능 여부를 함께 제어합니다.

출발 후 일정 시간이 지나면 강하게 감쇠시키던 타이머를 제거했습니다. `src/surface-friction.js`는 기존 Perlin 함수를 합성한 고정 유리 위치 노이즈와 방울별 부착 계수로 마찰을 계산합니다. 매 스텝의 실제 곡선 이동 길이에 따른 감쇠와 시간에 따른 표면 마찰을 함께 적용하고, 큰 질량은 거리 감쇠를 덜 받습니다. 기존 굴곡 저항과 회복은 유지합니다. 정지는 0.5–1초이며 크기가 클수록 기본 정지 시간이 짧고, 접촉 위치·방울 고유 값·정지 회차에 따라 분산됩니다. 초기 Heartfelt 방울도 서로 다른 속도·정지 상태로 시작합니다.

충돌 시에는 실제로 늘어난 물의 비율만큼만 이동을 보충하고, 작은 접촉은 기존 정지 시간을 끊지 않습니다. 크기 상한에 도달한 방울이 반복 접촉만으로 매번 최고 속도로 복귀하던 경우도 방지합니다.

이동·충돌은 고정 30Hz로 갱신하고 렌더링과 영상은 독립적으로 갱신합니다. 한 프레임의 따라잡기 계산을 최대 두 번으로 제한해 무거운 프레임에서 물리 계산이 계속 누적되는 현상을 막습니다.

동시 생성된 6px 방울 100개를 충돌·추가 생성·경로 노이즈 없이 실행한 비교에서, 이전에는 모두 0.733초에 멈췄지만 변경 후 첫 정지 시점은 0.52–8.25초(가운데 80개는 0.82–3.15초)로 분산됐습니다. 이 수치는 해당 고정 시드 실험 결과이며 모든 조건의 정지 시간을 제한하는 값은 아닙니다. 전체 자동 테스트 305개에서 생성량·불규칙 간격·0% 처리·셰이더/충돌 일치·정지 분산·30/60/120Hz·일시정지·반복 접촉과 기존 기능을 검증합니다.

## 웹 화면 공유 배경 — 2026-10-08

메뉴의 `화면 공유로 배경 바꾸기`를 누르고 영상이 재생 중인 다른 탭이나 창을 선택합니다. 공유 화면을 이 웹페이지 안에서 배경으로 사용하고, 동일한 프레임으로 물방울 굴절·블러·김서림을 처리합니다. 영상 재생·탐색은 원래 탭이나 창에서 조작합니다. `화면 공유 종료`나 브라우저의 공유 중지를 누르면 숲 배경으로 돌아옵니다. 그리기는 `그리기 모드` 버튼 또는 G 키로 켜고 끕니다. 입력란에서 타이핑할 때 G 키는 전환하지 않습니다.

Electron 없이 기존 `npm start`와 브라우저만 사용합니다. 화면 공유는 HTTPS 또는 localhost에서 브라우저의 선택창을 통해 연결합니다. 현재 탭 제외와 공유 탭 전환 옵션은 [Chrome 화면 공유 문서](https://developer.chrome.com/docs/web-platform/screen-sharing-controls)를 따릅니다. 공유 화면의 음성은 요청하지 않으며 원래 영상의 소리는 원래 탭에서 재생됩니다. 음악 반응 연결은 별도 기능입니다.

`src/screen-share.js`는 선택·취소·해제와 늦게 도착한 연결을 관리하고, `src/shared-background.js`는 한 영상 스트림을 최대 긴 변 1920px·초당 30회로 갱신합니다. 공유 중에는 배경 패럴랙스를 끕니다. 페이지 이탈·연결 실패·공유 종료 시 모든 공유 트랙을 해제합니다.

전체 자동 테스트 296개 통과. 화면 공유 관련 9개 테스트에서 중복 요청, 취소 뒤 도착한 스트림 정리, 읽기 실패·시간 초과, 공유 중지, 프레임 갱신과 크기 제한을 확인했습니다. 브라우저에서 버튼·G 키 전환 및 공유 요청 상태를 확인했고 오류·경고 로그는 없었습니다. 실제 다른 탭/창을 선택한 이후의 영상과 굴절은 아직 실환경 검증 전입니다.

## 큰 물방울의 경로 너비 수정 — 2026-10-08

Heartfelt 물방울의 경로 반지름을 3.2px로 제한하던 코드를 제거했습니다. 김서림을 닦는 경로에도 반지름의 32.5% 대신 렌더링에 사용하는 늘어남·퍼짐·회전과 현재 이동 방향으로 계산한 몸통 너비를 적용합니다. 합체 후 커진 방울과 작은 방울 모두 크기에 비례한 물길을 남기며 기존 복구 시간은 유지합니다. 전체 테스트 287개 통과: 두 종류의 합체 방울 성장, 몸통 가장자리의 마스크, 기울어진 경로, 작은 경로의 연속성과 복구를 확인했습니다. 브라우저에서 드래그·재개 후 넓어진 경로를 확인했고 오류·경고 로그는 없었습니다.

## 손가락 접촉으로 물방울 모으기 — 2026-10-08

손가락의 현재 이동 선분과 두께에 닿은 미세 방울·일반 물리 방울·Heartfelt 이동 방울을 합쳐 흐르게 합니다. `BeadField.peekFinger`는 셀 그리드에서 해당 구간만 찾으며, 보이지 않는 셰이더 방울과 죽은 방울은 제외합니다. 이미 닦인 김서림 마스크에는 충돌 기능을 연결하지 않습니다. 같은 물을 다시 합산하지 않도록 흡수한 미세 방울을 필드와 셰이더에서 제거하고, 이동 방울은 한 몸만 남깁니다. 합체는 새로운 생성음 신호를 내지 않습니다.

손가락 합체의 면적은 반지름 제곱을 100% 합산하고, 위치는 면적 가중 평균으로 정합니다. 반지름은 합산 면적의 제곱근, 질량은 합산 면적 × 질량 배율, 출발 속도는 질량 × 9.81입니다. 손가락으로 모은 방울에는 일반 생성 방울의 반지름 14.4px 상한을 적용하지 않으며, 이후 흡수에도 이 성질을 유지합니다. 큰 방울의 충돌 그리드 탐색 범위를 넓히되 실제로 방울이 있는 셀 범위로 제한합니다. 기존 노이즈·굴곡 감속·마찰·정지는 출발 후 계속 적용됩니다. 전체 이동 방울이 1320개이고 재사용할 접촉 방울이 없으면 새 몸을 만들지 않고 원래 미세 방울을 유지합니다.

전체 테스트 284개 통과: 이동 구간 충돌, 두 렌더러와 미세 방울의 합산 질량·크기·속도, 실제 하강, 중복 합산 방지, 과거 그림의 비활성, 셰이더 제거와 생성음 없음, 크기 상한 이후 물 보존, 넓어진 그리드 충돌과 개수 제한을 확인했습니다. 브라우저에서 드래그 후 접촉 부위의 방울 변화와 재개 화면을 확인했고 오류·경고 로그가 없었습니다. 이는 기존 면적 기반 표현 모델의 확장이며 정밀한 유체 해석은 아닙니다.

## 김서림에 손가락으로 그리기 — 2026-10-08

문지르는 동안은 `assets/finger-cursor.svg`의 검지 손 모양 커서를 사용하고, 해제·취소 시 십자 커서로 돌아갑니다. 브라우저에서 누르는 동안의 커서 스타일과 해제 후 복구를 확인했으며, 관련 드로잉·서버 테스트 9개와 SVG의 HTTP 200 / `image/svg+xml` 응답을 검증했습니다.

창문을 마우스 왼쪽 버튼으로 누르고 드래그하거나 터치·펜으로 문지르면 약 28 CSS px 두께의 투명한 선이 남습니다. `src/finger-drawing.js`가 한 포인터를 캡처하여 빠른 이동도 선분으로 이어 주며, 오른쪽 클릭·호버·추가 손가락은 그리지 않습니다. 시점 이동은 그리는 동안 고정하고 유리의 확대·패럴랙스 좌표를 역변환하여 포인터와 선을 맞춥니다. 취소·창 포커스 이탈·초기화·크기 변경·풍경 보기에서 진행 중인 획을 끊습니다.

기존 물길의 `TrailMemory`와 김서림 마스크를 사용하며, 닦인 곳은 마지막 터치부터 1.5초 동안 선명하게 유지한 뒤 1초 동안 다시 서립니다. 다시 문지른 곳만 시간이 갱신됩니다. 물방울은 별도로 유지하며, 포인터 이벤트가 몰려도 마스크 업로드는 다음 그리기에서 한 번만 수행합니다. 일시정지 중에도 그릴 수 있고 복구 시간은 재개할 때부터 흐릅니다. `다시 맺히기`는 그림도 지웁니다.

전체 테스트 276개 통과. 포인터 연결·터치·펜·취소, 좌표와 두께, 마스크 갱신·복구·기존 물길 유지 및 기존 기능을 검증했습니다. 브라우저에서 마우스 드래그로 A를 그리고 투명한 선을 확인했으며, 재개 후 다시 서려 사라지는 모습과 오류·경고 로그 없음도 확인했습니다. 실제 터치 기기 검증은 하지 않았습니다.

## 물방울 크기에 따른 정지 시간 — 2026-10-08

흐르던 방울이 멈추는 순간의 반지름으로 정지 시간을 정합니다. 기존 경로 phase 기반 시간 대신 `1 - 0.5 × clamp(반지름 / 14.4, 0, 1)`초를 사용하여 작은 방울은 1초에 가깝게, 최대 크기는 0.5초 동안 멈춥니다. 일반 물리 방울과 Heartfelt 이동 방울에 공통 적용하며, 기존 합체·충분한 미세 방울 흡수에 의한 조기 재출발은 유지합니다. 관련 테스트 31개 통과: 크기별 시간과 순서, 30/60/120Hz 재출발 시점, 정지 중 위치 유지, 마찰·굴곡 감속·충돌 등을 확인했습니다.

## 빗소리 음량 자동 보정 ON/OFF — 2026-10-08

메뉴의 동시 빗소리 수 아래에 음량 자동 보정 버튼을 추가했습니다. 기본 ON은 소리와 교체 꼬리의 합이 12개를 넘으면 `12 / 개수`로 감쇠하고, OFF는 이 배율을 1로 유지합니다. 재생 중 전환할 수 있으며 AudioWorklet과 노드 대체 경로 모두 적용됩니다. 빗소리 재연결·물방울 초기화 후에도 설정을 유지하지만 페이지 새로고침 시에는 기본 ON으로 돌아갑니다. OFF에서는 많은 소리가 겹칠 때 출력이 커져 클리핑될 수 있습니다.

관련 테스트 28개 통과: 밀집 믹서의 ON/OFF 출력, 기존 노드 소리의 즉시 반영, 새 Worklet 초기 설정과 재연결 유지 등을 검사했습니다. 브라우저에서 ON/OFF 표시와 초기화 후 OFF 유지, 실제 Worklet 재생을 확인했고 오류·경고 로그는 없었습니다.

## 하단에 고이는 물

수면에 도착한 물리 방울은 제거되어 물의 양에 합산됩니다. 표시용 환산은 방울 면적 질량 × 2.5 / 화면 면적이며 수위는 최대 30%입니다. 10%부터 `물 비우기`가 활성화되고 초당 화면 높이 7.5%씩 빠집니다. 배수 중 들어오는 물은 함께 배출합니다. 수면에는 두 겹의 잔물결과 최근 방울 충돌 파문을 표시합니다. 물속은 원본 배경을 굴절해 보여주며 배경 디버그 블러와 김서림을 덮어 숨깁니다. 실제 김서림 상태와 물길 기록은 지우지 않으므로 배수로 드러난 유리에 기존 상태가 그대로 돌아옵니다. 일시정지는 수위 증가·파동을 멈추지만 요청한 배수는 완료됩니다. 풍경 보기는 물도 숨기며 초기화는 수위도 비웁니다.

현재 최대 반지름은 20px입니다. 생성 반지름 4~10px는 기존 하강 속도를 유지하고 10~20px에서 크기 보정이 1.0~1.3배로 증가합니다. 고음 가속과 독립적인 계수여서 무음·고음 구간 모두 같은 크기 비율이 적용됩니다. 속도 상한도 같은 계수를 적용하며, 크기 변화 후 실제 속도는 가속·감쇠를 통해 부드럽게 바뀝니다.

아주 작은 Canvas 방울도 이제 공간 격자에 등록해 흐르는 방울과 접촉 시 실제 질량으로 흡수됩니다(장식 방울 최대 22,200개). 흡수 위치 쪽으로 향하는 힘에 사건별 0.65~1.75 배 변화를 주고, 감쇠를 1.8로 줄여 대각선 하강이 조금 더 이어집니다. 힘의 상한 ±120은 유지합니다. 꼬리 방울 반지름 비율을 10~16%로 줄여 흡수에 의한 성장과 상쇄되는 질량 손실을 낮췄습니다. 아래 이전 물길 계수 설명보다 이 값이 우선합니다.

흐르는 방울이 다른 방울을 흡수하면 흡수 위치의 좌우 차이와 질량 비율에 따라 짧은 횡방향 힘을 받습니다. 힘은 최대 ±120px/s²로 제한하고 초당 지수 감쇠 2.4로 줄여 서서히 원래 하강으로 돌아갑니다. 무작위 흔들림은 추가하지 않았으며, 합체 전후 중심 사이에도 물길 마스크를 이어 그립니다. 이는 표면 장력에 의한 경로 변화를 표현하는 근사 효과입니다.

최신 음악 최대값: 음량에 따른 일반 빗방울 생성은 최대 38.1개/초(기존 25.4의 1.5배), 고음 최대 하강 가속도는 1116(기존 744의 1.5배), 속도 상한은 540px/s(기존 360의 1.5배)입니다. 무음 생성 1.4개/초와 기본 가속도 144는 유지합니다. 전체 방울 420개 제한은 유지하며 포화 시 추가 생성은 제한됩니다. 아래 이전 수치보다 이 설정이 우선합니다.

물길의 김서림 복구는 고정 시간입니다(추가 슬라이더 없음). 마지막 통과 후 1.5초 동안 맑게 유지하고 1초 동안 감쇠하여 주변 김서림 농도로 돌아옵니다. 마스크 픽셀별 마지막 통과 시간을 기록하므로 재통과한 자리만 갱신됩니다. 일시정지 중에는 복구 시간도 멈추며 창 크기 변경 시 물길의 나이를 보존합니다. 배경 블러·전체 김서림 생성 및 제거 설정은 유지합니다.

하단 `디버그 · 배경 블러`에서 배경 텍스처의 블러를 0~24px(0.5 간격)로 조절할 수 있습니다. 0은 원본이며 새로고침하면 0으로 초기화됩니다. 김서림 상태·생성 시간·제거 시간·물길 마스크는 변경하지 않습니다. 기본 배경과 기존 김서림 텍스처에 동일한 추가 블러를 적용하며 물방울 굴절용 원본 텍스처는 별도로 유지합니다. 값 변경 시에만 텍스처를 갱신합니다.

현재는 베이스 전용 효과와 튀는 방울 생성 로직·표시를 제거했습니다. 음악 매핑은 **전체 음량 → 생성량**, **고음 → 하강 속도** 두 가지입니다. 아래 베이스 튀기 관련 내용은 이전 버전 기록입니다. 저음도 전체 음량 측정에는 포함되지만 별도의 물리 효과는 없습니다.

## 현재 음악 매핑: 음량 / 베이스 / 고음

- 전체 음량(RMS): 일반 빗방울 생성량을 초당 1.4~25.4개로 조절합니다. 무음 기본 비는 유지합니다.

## 2026-09-20: 표면 물리와 외부 음악 반응

큰 방울 위주의 초당 약 15개 생성에서 작은 방울 중심의 기본 초당 약 1.4개 생성으로 변경했습니다. 물방울은 정지 상태에서 맺히고, 크기·합체·기울기·음악 강도에 따라 잠깐 미끄러진 후 마찰로 완전히 멈춥니다. 가로/세로 퍼짐 복원과 늘어진 꼬리 표현을 추가했습니다. 처음 물방울의 선택 고정은 유지됩니다.

하단 **음악에 반응하기 → 음악 연결**로 공유 창을 엽니다. 유튜브/Spotify 웹은 해당 탭과 탭 오디오 공유를 선택하고, 데스크톱 앱은 지원되는 브라우저에서 전체 화면과 시스템 오디오 공유를 선택합니다. 오디오 공유 지원은 브라우저/OS에 따라 달라집니다. Chrome 또는 Edge에서 이 로컬 주소를 직접 여는 방법을 권장합니다. 내장 브라우저가 공유를 지원하지 않으면 안내가 표시됩니다.

마이크 API는 사용하지 않습니다. getDisplayMedia는 화면 트랙을 요구하므로 공유 창에서 화면도 요청되지만, 영상 트랙은 비활성화하며 렌더링·저장·전송하지 않습니다. 오디오는 Web Audio에서 로컬 분석하며 재출력하지 않습니다. 연결 해제·공유 종료·페이지 이탈 시 모든 공유 트랙과 AudioContext를 정리합니다.

- 저음/베이스(40–250Hz): 작은 물방울 생성량만 조절합니다. 기본 초당 1.4개에서 강한 베이스에 최대 25.4개까지 증가하며, 전체 개수 제한을 적용합니다. 큰 물방울 위주의 분포로 바뀌지는 않습니다.
- 고음(2–8kHz): 기본 하강 가속도 144를 유지하고 고음에 따라 최대 600을 추가합니다(최대 744). 고음 추가 가속을 이전의 두 배로 강화하고 하강 속도 상한을 220에서 360px/s로 높였습니다. 음악 없는 기본 흐름은 유지하며 고음이 사라지면 부드럽게 복귀합니다. 선택된 방울은 물길을 남기며 작아져도 최소 하강 계수 0.75를 유지합니다. 미끄러짐 빈도·지속 시간 반응은 유지하며, 고음만으로 생성량이 늘지는 않습니다.
- 음량(RMS)은 입력 확인과 무음 판정에 사용합니다. 전체 음량과 박자 후보는 물리에 직접 중복 적용하지 않습니다.
- 저음 1.6배, 고음 2.4배 입력 보정 및 빠른 상승/느린 감쇠를 적용합니다. 반응 강도 슬라이더를 곱한 최종 대역값을 표시합니다.
- 다성 음악의 단일 피치를 추정하지 않고 주파수 대역을 변수로 사용합니다.
- 소리가 작아지면 반응이 줄고 기본 비로 복귀합니다. 반응 강도 슬라이더로 조정할 수 있습니다.

일시정지/풍경 보기는 시뮬레이션만 멈춥니다. 공유 자체를 끝내려면 음악 연결 해제를 누르세요. 실제 Spotify/유튜브 시스템 오디오 캡처는 사용자가 공유 대상을 선택해야 하므로 아직 실환경 검증 전입니다. 자동 검증은 주파수 분리·정지/재출발·큰 방울 감소·음악에 따른 흐름 증가·오디오 없는 공유 정리와 기존 선택 유지 동작을 포함합니다.

Node.js 18 이상에서 이 폴더를 열고 `npm start` 실행 후 http://127.0.0.1:4173 에 접속합니다. 패키지 설치는 필요하지 않습니다. 실행 중 포트가 사용 중이면 `PORT` 환경 변수로 변경할 수 있습니다.

## 조작

- ← / → 키를 누르고 있거나 화면을 좌우로 드래그하면 중력이 기울어집니다.
- 화면의 방향 버튼을 누르거나 길게 눌러도 움직입니다.
- 처음 지정된 물방울이 조작 대상입니다. 다른 방울을 눌러도 바뀌지 않으며, 합체할 때도 같은 물방울이 유지됩니다.
- 물방울은 만나면 합쳐지고, 지나간 물길은 현재 설정 기준 1.5초 유지 후 1초 동안 재결로됩니다(총 2.5초).
- 아래 또는 좌우로 완전히 빠져나가면 새 물방울이 위쪽에 생깁니다. 다시 맺히기는 전체 상태를 초기화합니다.
- 잠시 멈추기 / 다시 맺히기 / 풍경 보기를 지원합니다.
- 휴대폰 기울이기 버튼은 권한 승인 뒤 현재 자세를 기준으로 좌우 입력을 받습니다. 화면 회전 시 기준을 재설정합니다. 센서 없음·거부 시 드래그를 사용할 수 있습니다.

## 모바일 확인

실제 기울기 센서는 휴대폰에서 접근할 수 있는 HTTPS 주소가 필요합니다. 이 개발 서버는 PC의 localhost에만 열립니다. 실제 휴대폰 센서 동작은 아직 검증하지 않았습니다. 현재 폴더의 HTML/CSS/src/assets를 HTTPS 정적 호스팅에 올리면 사용할 수 있습니다. 서버 스크립트와 tests 폴더는 배포 대상이 아닙니다.

## 구조 및 원본 활용

- `src/physics.js`: 초 단위 고정 스텝, 2D 면적 질량, 합체, 선택, 기울기 이동. 3D 유체 시뮬레이션이 아닙니다.
- `src/raindrops.js`: 원본의 drop-alpha/drop-color 스프라이트 합성 방식, 별도 물길 마스크.
- `src/shaders/water.frag`: 원본 RGBA 방향·두께 해석을 기반으로 습기 합성과 굴절을 추가한 셰이더.
- `src/rain-renderer.js`: 단일 렌더 루프에서 호출되는 WebGL 렌더러. uniform 캐싱, 고정 버퍼, 텍스처 재사용, DPR 1.5 상한.
- `src/input.js`: 키보드·포인터·기울기 센서 입력 통합, 권한·시간 초과 처리.
- `src/create-canvas.js`, `src/shaders/simple.vert`: 원본 활용.
- 원본 index/index2/index3의 이미지·광택·동영상 흐름을 검토했으며, 첫 버전은 정적 배경 방식입니다. 동영상과 광택 이미지 사용은 후속 확장 대상입니다.
- 원본의 Gulp/Babel 5 의존성 대신 브라우저 기본 ES modules를 사용합니다.

원본 폴더는 수정하지 않았습니다. 현재 버전은 레퍼런스 Weather 데모의 texture-rain-bg.png와 texture-rain-fg.png를 사용합니다. 추가 블러·어두운 틴트·배경 문구를 제거했습니다. 원본 알파 보정(6배 후 3 차감), 굴절 범위(256–512), 미세 결로 누적·쓸림을 복원했으며, 배경에 선명한 텍스처를 24% 섞어 흐림을 줄였습니다. 물길은 결로 입자를 쓸어내고 배경을 조금 더 선명하게 만듭니다.

주변 빗방울은 자동으로 낙하·합체하며 작은 꼬리 방울을 남깁니다. 조작하는 물방울은 첫 입력 전까지 기다립니다. 렌더링은 원본에 가깝게 조정했지만 물리는 초 단위 입력·선택 고정을 지원하도록 수정한 근사 모델입니다. 원본과 픽셀 단위로 동일한 복제는 아닙니다.

물리 검증: `npm test`. 키보드·드래그·선택·합체·다시 시작·리사이즈를 브라우저에서도 확인할 수 있습니다.

## 이번 버전에서 확인한 항목

- 물리 자동 검증 6개 통과: 합체 질량·운동량, 좌우 이동, 정지·선택 유지, 재생성·크기 변경, 다른 방울 클릭 차단, 더 큰 방울과 합체 시 동일 객체 유지 및 옆으로 이탈 시 교체.
- 브라우저에서 WebGL 렌더링, 미세 결로와 흐르는 물방울, 방향 버튼·드래그 입력, 정지, 초기화, 풍경 보기를 확인했습니다. 배경 문구는 제거됐습니다.
- 390×844, 375×667 크기에서 조작부 배치와 가로 넘침을 확인했습니다.
- 센서 신호가 없는 데스크톱에서 시간 초과 후 대체 조작 안내를 확인했습니다.
- 브라우저 콘솔 오류 없음. 실제 iOS/Android 센서, WebGL 컨텍스트 복구, GPU 미지원 폴백은 아직 실기기 검증 전입니다.
